# PROJECT_PROFILE

## Identidad y repositorios

- Proyecto: `magictheorem-map`.
- Repositorio del producto (privado): `FAJIFBEFJHA/magictheorem-map`.
- Repositorio del workflow (público): `FAJIFBEFJHA/ai-assisted-development-workflow`.
- Propósito: crear un beatmap de osu!standard y, después, un storyboard.
- Entorno de trabajo: Windows; editor del beatmap: osu!lazer.
- Tecnología prevista para el storyboard: Storybrew/C#.

El repositorio privado conserva los archivos del beatmap y la documentación propia del producto, incluidas sus decisiones artísticas y su planificación. Este directorio público conserva únicamente reglas de colaboración y el checkpoint mínimo para retomar sesiones de IA. No se duplican aquí recursos artísticos, audio, capturas ni documentación privada detallada.

## Responsabilidades

- El usuario toma las decisiones artísticas y realiza el mapping.
- La IA puede ayudar con documentación, análisis técnico y revisión cuando el usuario lo solicite.
- La IA no implementa código Storybrew ni otro código por iniciativa propia.
- La documentación puede redactarse o revisarse en colaboración por solicitud del usuario.
- Las explicaciones se dan en español; los identificadores técnicos se escriben en inglés cuando corresponda.

## Verificación y control de versiones

- La comprobación del gameplay se hace manualmente en osu!lazer; no se presupone una prueba automatizada.
- Antes de afirmar que un archivo existe, está versionado o llegó al remoto, comprobar el repositorio y el estado de Git correspondientes.
- Mantener separados los commits y la sincronización de los repositorios de producto y workflow. No dar por publicado un cambio local hasta verificar su push.
